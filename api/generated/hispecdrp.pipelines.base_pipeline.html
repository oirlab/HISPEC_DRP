_filter_processing_mode(candidates)[source]

Filter candidates by the processing mode (self.context.processing_mode).

Unlike quicklook, processing_mode has no natural default value, so an unspecified input (None) leaves the candidates unconstrained. When a value is specified, a config file that explicitly matches it always wins; a config file that omits processing_mode (None, a wildcard) is only used as a fallback when nothing explicitly matches.

Parameters:

candidates (list[ConfigFile]) – List of candidate config files to filter.

Returns:

filtered_candidates (list[ConfigFile]) – The filtered list of config files that match the processing mode criteria.

_filter_quicklook(candidates)[source]

Filter candidates by the quicklook flag (self.quicklook).

A config file that omits quicklook (context value None) is a wildcard: it matches any requested value. It’s only used as a fallback when no candidate explicitly matches the requested value, so an explicit True/False config always takes precedence over a wildcard one for the same class.

Cases

  1. Input context = None ConfigFile contexts = (None, …) -> All ConfigFile contexts = (True, False) -> False

  2. Input context = False

    ConfigFile contexts = (True, False) -> False ConfigFile contexts = (None, …) -> All

  3. Input context = True

    ConfigFile contexts = (True, None) -> True

param candidates:

List of candidate config files to filter.

type candidates:

list[ConfigFile]

Returns:

filtered_candidates (list[ConfigFile]) – The filtered list of config files that match the quicklook criteria.

_select(meta, candidates)[source]

Internal method to perform the core config file selection logic.

This method first retrieves a set of candidate config files using get_candidates and then selects the best one (or ones) from these candidates using select_best. Subclasses can override this method to implement custom selection workflows, but it’s often more appropriate to override get_candidates or select_best.

Parameters:

  • meta (dict) – The metadata for which a config file is to be selected.

  • candidates (list[ConfigFile]) – The list of candidate config files to consider.

Returns:

result (ConfigFile | None) – The selected config file if one is found, otherwise None.

get_output_dir(model)[source]

Get the output directory for saving any results in the context of a model. The priority for determining the output directory is as follows:

  1. self.output_dir if explicitly set (input model not used).

  2. model._filepath directory if available If an input model is provided, the fallback is the directory of self.dataset.

  3. Current working directory as a final fallback.

Parameters:

model (str | DataModel) – The input model to determine the output directory from if self.output_dir is not set.

Returns:

str – The output directory for saving results.

logging_context(config_dict, queue=None)[source]

The single entry point for all logging in hispecdrp.

Outermost call owns the queue and listener for its full lifetime. Nested calls (e.g. a pipeline invoking a primitive that also calls logging_context) are no-ops — they yield immediately without touching the queue, so the outer context stays alive.
