calibration_record_in_cache(cal, mode='id')[source]

Checks if a calibration is already present in the local cache.

Parameters:

  • calibration (dict | str | DataModel) –

    Can be one of:

    • str : A calibration ID string or filepath.

    • dict : A calibration metadata dict.

    • DataModel : A calibration data model instance.

  • mode (str) –

    The mode to check the cache. Can be one of:

    • ’id’ : Check by calibration ID (cal_id), the primary key in the database.

    • ’version-family’ : Check by the version family (cal_type, datetime_obs, master_cal, spectrograph) + version (cal_version).

    • ’md5’ : Check by the MD5 checksum of the calibration file (Not Implemented yet!).

Returns:

dict | None – The calibration metadata record if found, otherwise None.

register_calibration(cal, origin=None, new_version=False)[source]

Registers a calibration to the local cache and metadata database.

Parameters:

  • cal (CalibrationModel | str) – The filepath or Calibration Datamodel object to register.

  • origin (str, optional) – The origin to register the calibration under.

  • new_version (bool, optional) – Whether to generate a new version for this calibration. If False, the method will check if a calibration with the same version family already exists in the cache and skip registration if so. Defaults to False.

Returns:

tuple[str, dict] –

A tuple containing:

  • str: The local file path where the calibration was saved.

  • dict: The calibration metadata dictionary as added to the database.

Notes

Upstream koa_middleware.CalibrationStore.register_calibration snapshots cal.to_record() before cal.save() and discards the return value of generate_calibration_version, so filename / koa_id / cal_version can be stored as None even though the FITS file is written. This override assigns those fields on the model and record before insert, and returns any existing version-family match instead of (None, None).

select_and_get_calibration(input, selector)[source]

Selects the best calibration based on input data and a selection rule, then retrieves it.

This method uses a CalibrationSelector to identify the most appropriate calibration for the given input data. Once selected, it retrieves the calibration file, downloading it if it’s not already cached locally.

Parameters:

  • input – The input data product for which a calibration is needed.

  • selector (CalibrationSelector) – An instance of a CalibrationSelector class.

Returns:

  • tuple[str, dict] –

    • str: The local file path of the retrieved calibration file.

    • dict: The record of the selected calibration from the local database.

  • Example – >>> # Assuming my_input_data and my_selector are defined >>> local_filepath, calibration_record = store.select_and_get_calibration(my_input_data, my_selector) >>> print(f”Calibration file: {local_filepath}”) >>> print(f”Calibration ID: {calibration_record[‘id’]}”)

sync_records_from_remote(cals=None, mode='id')[source]

Synchronize the local DB with the remote KOA catalog.

cals is accepted for compatibility with callers that pass an explicit remote query result; when omitted, records are discovered via get_missing_records (same as koa_middleware).

Remote metadata failures (e.g. KOA API 404) are logged and treated as a no-op so pipelines can continue with the local caldb/cache. Callers that need a hard failure should inspect logs or sync explicitly with their own error handling.
