classmethod _doc_default_detector_size()[source]

Resolve (ny, nx) purely to render real numbers in a generated extensions table’s Dimensions column (see extensions_table()) – from cls._DEFAULT_INSTRUMENT’s config, since this runs from __init_subclass__() at class-definition time, before any instance (and so any live self.config/self.default_detector_size, which a multi-detector model could have overridden) exists.

Deliberately does not go through utils.get_instrument_config() (which reads INSTRUMENT_CONFIGS, a dict this very package’s __init__.py only builds after importing every model class – every __init_subclass__ call happens before it exists). Instead imports <instrument>_config directly by name, matching this package’s own hispec_config.py/parvi_config.py convention – that submodule only needs base_model/meta_data, already loaded by the time any model class is being defined, regardless of how far this package’s own __init__.py has otherwise gotten.

Never raises; None (axes stay symbolic, e.g. Ny/Nx) if the default instrument’s config can’t be resolved this way or has no DETECTOR_SIZE.

_infer_shape_symbols()[source]

Scan every currently-set image extension and, for each, match its real array shape positionally against its own declared shape= spec (see extensions.IMAGE_HDU(); populated for every extension, even one that omitted it itself, by _populate_shape_info() at construction time), recording {symbol: size} for every non-literal, non-ANY symbol position.

This is what lets e.g. an explicitly-assigned model.bias = np.ones((10, 10)) inform the shape used to auto-init model.ktc, model.dq, etc. on that same model – nothing is hardcoded about “bias” being special; any extension whose declared shape shares a symbol with another can inform it, as long as it’s actually been set. Also the only source N_READS (no independent resolver – see _resolve_shape_axis()) ever has.

_make_default_array(extname, info)[source]

Lazily build the default array for an image extension, if eligible.

If the extension declares 'default' (see extensions.IMAGE_HDU()) and its 'shape' spec (populated for every extension by _populate_shape_info() at construction time) fully resolves (see _resolve_shape()), the array is built directly as np.full(resolved_shape, default, dtype=...). Otherwise, building it is delegated to make_default_array() – tried unconditionally, whether or not default was given – which subclasses can override for extensions whose shape can’t be expressed with the available symbols (e.g. polynomial coefficients, a per-instance fit result).

classmethod _populate_shape_info(extensions)[source]

Fill in 'shape' for any image extension that omitted it (see extensions.IMAGE_HDU()’s shape=None), copying the primary extension’s declared shape – the first key not in the reserved special names (PRIMARY, RECEIPT, DATA_ANCESTORS, CALIBRATIONS), matching the base primary_extension_name default. A copy of the info dict is only made where a fill-in is actually needed, so shared info dicts (e.g. DQ_L0, reused as-is across many models) are never mutated in place.

A model with a dynamic primary_extension_name override (returning None until some fiber’s data is actually set) can’t rely on this – it always declares every extension’s own shape= explicitly, so there’s nothing left here to fill in for it.

_resolve_shape_axis(axis, inferred)[source]

Resolve one axis of a shape= spec (see extensions.IMAGE_HDU()) to a concrete size, or None if it can’t be resolved on this model right now.

A string axis is matched case-insensitively against the recognized symbolic names (DETECTOR_SIZE_Y, DETECTOR_SIZE_X, N_ORDERS, N_FIBERS, N_READS, ANY). Checked in order: (1) inferred (see _infer_shape_symbols()); (2) the symbol’s own independent source, if it has one – DETECTOR_SIZE_Y/ DETECTOR_SIZE_X fall back to the constructor’s shape= override, then default_detector_size; N_ORDERS to meta.order_start/order_end; N_FIBERS to config.num_fibers. N_READS and any other symbol with no independent source are only ever resolvable via inferred. ANY is never resolvable at all, by design.

property default_detector_size

This model’s (ny, nx) detector plane size – the last-resort source for the DETECTOR_SIZE_Y/DETECTOR_SIZE_X shape-symbol resolvers (see _resolve_shape_axis()) when no extension’s already-set real data and no explicit constructor shape= override provide it instead.

Defaults to config.DETECTOR_SIZE, which is all a single-detector instrument ever needs. An instrument with multiple, differently sized detectors has no single automatic answer – override this property (in a subclass, or an intermediate base shared by that detector’s models) to compute the right one from whatever instance state actually distinguishes them, e.g.:

@property
def default_detector_size(self):
    return self.config.DETECTOR_SIZES.get(self.meta.instrument_mode)

property shape

The shape of the model’s primary extension.

Reads the primary extension’s raw value (never triggers lazy auto-initialization). If the primary extension has no real array yet, falls back to the shape= override passed to the constructor, else None.

Note this is unrelated to auto-init’s own shape resolution (see _resolve_shape_axis()), which no longer depends on this property or primary_extension_name at all – it resolves each symbol (DETECTOR_SIZE_Y, N_ORDERS, etc.) independently, so this property stays a simple, general-purpose reflection of “what’s actually been assigned to the primary extension” for any other code that reads model.shape directly.

_correct_image_dtype(data, dtype_spec, extname='')[source]

Cast an image extension’s array to its declared dtype, if needed.

dtype_spec is an extension’s declared 'dtype' entry (see extensions.IMAGE_HDU()): a single numpy scalar type, or a precedence-ordered tuple of them for extensions with more than one legitimate dtype (e.g. RampModel.DATA: uint16 for real detector data, float32 for simulations run with convert_to_uint16=False).

If data’s dtype already matches one of the declared choices (subtype-wise), it’s returned unchanged. Otherwise the declared choice sharing data’s broad numeric family (see _dtype_family() – e.g. any integer array matches a declared integer dtype, any float array matches a declared float dtype) is used as the cast target, falling back to the first (canonical) declared dtype if none share that family.
